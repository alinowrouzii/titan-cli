# Titan CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Local `titan` command that logs into EFARDA PAM, lists SSH accesses, and opens the same websocket shell the browser uses.

**Architecture:** Small Python package. Thrift binary over HTTP for login and access list. Websocket plus a raw local tty for the shell. Token stored in `~/.config/titan/session.json` mode `0600`. Password never stored.

**Tech Stack:** Python 3.9+, stdlib `urllib` and `termios`, `websockets` for the shell, pytest.

**Spec:** `docs/superpowers/specs/2026-10-20-titan-cli-design.md`

## Global Constraints

- Host default `https://titan.efarda.ir`. Override with `TITAN_URL`.
- Session path `~/.config/titan/session.json`, mode `0600`. Password never written.
- ef.net LDAP provider name is exactly `ef.net`. `federationId` is that provider's `id`.
- SSH accesses only: protocol enum `1`, resource types workstation `1`, server `2`, network device `3`.
- Shell URL: `wss://<host>/ssh-proxy?cols=&rows=&token=&sessionCookie=&destination=<access id>&protocol=ssh`.
- `sessionCookie` is a UUID with hyphens removed.
- Destination is the access `id` field (the Connect button uses that id).
- Zero name hits: exit 1. Many hits: print them, do not connect, exit 1.
- HTTP 403: tell the user to run `titan login`. Exit 1.
- No live PAM calls in tests.
- Login state `1` is AUTHENTICATED. States `2` GENERATE_OTP, `3` VERIFY_OTP, `4` CHANGE_PASSWORD: do not write a session. Tell the user to finish that in the browser.
- Page the access list. The browser asks for 10 rows. The CLI asks for 100 and repeats until every hit is collected.
- Ctrl-C byte goes to the remote shell, same as OpenSSH. Local tty is restored when the socket closes, the remote exits, or this process is signalled.

## Protocol facts

POST body is strict TBinaryProtocol. No frame length. `Content-Type: application/octet-stream`. When a token exists, `Authorization: Bearer <token>`.

Paths:

- `POST /api/auth/auth` methods `externalProviders` and `login`
- `POST /api/identity/accesses` method `getSelfAllowedAccess`

`login` args: field 1 struct LoginInput. LoginInput fields: 1 username string, 2 password string, 3 federationId string.

`login` result: field 0 LoginResponse, field 1 empty invalid-credentials struct. LoginResponse fields used: 4 token string, 6 state i32, 8 sessionId string.

`externalProviders` args: empty struct. Result field 0 LoginProviders. Field 1 list of LDAP structs (1 id string, 2 name string). Field 3 banner string.

`getSelfAllowedAccess` args: field 1 AllowedAccessSearch. Search fields: 1 filters struct, 2 skip i32, 3 limit i32. Filters: field 1 list of protocol unions (`equals` = i32 `1`), field 7 list of resource-type unions (`in` = i32 list `1,2,3`).

List result field 0: field 1 total i32, field 2 hits. Each hit: 1 id, 2 name, 3 resource_name, 4 resource_ip. All strings.
